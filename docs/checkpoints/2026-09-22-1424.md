## Decisions

- **The engine/policy boundary for the polydoc extraction**: everything
  that reads as "generic multi-language triple-source document
  assembly" (content units, root docs, the transaction writer, the
  registry machinery, structural checks, the heading scanner) moved to
  polydoc; everything that is ktav's own release-consistency policy
  (`drift.mjs`'s `versions.ktav` parser and anchor regexes,
  `DOCS_REGISTRY`'s actual file list, `KNOWN_SOURCE_DEFECTS`) stayed in
  spec as a thin thin wrapper layer.
- **Internal branding strings inside polydoc were deliberately kept
  ktav-flavored** (`.build-spec.transaction.*` file names,
  `KTAV_BUILD_SPEC_CRASH_*` env vars, `--write-frozen-lock` in error
  text) rather than genericized, specifically to avoid touching ~15
  existing spec test files that assert on those exact strings. Flagged
  as a known cosmetic debt for a future real-genericization pass, not
  fixed now.
- **polydoc consumed via `file:../polydoc` npm dependency** (real
  package resolution, npm-managed symlink into `node_modules`), not a
  bare relative import path — deliberately closer to how a real
  published dependency will actually be consumed, while staying 100%
  local/offline for now.
- **Subagent delegation for the OpenSource-conventions survey was
  granted "this once, then do it yourself"** — the user explicitly
  declined to extend blanket subagent authorization to the rest of this
  task, unlike the earlier `/wrush` authorization for the six-binding
  migration.
- **npm publish was explicitly out of scope** for this session's
  OpenSource-prep request — the user asked for repo metadata/CI/tests,
  not registry publication; not attempted.
